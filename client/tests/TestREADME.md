
## 🧪 Client Test Suite Documentation

### **1. `access` (Accessibility)**

Focuses on ensuring the application is usable for everyone, including those using assistive technologies.

* **Keyboard Navigation:** Verifies that users can navigate the login/signup forms and popups using only the `Tab` and `Enter` keys.
* **Screen Readers:** Checks for proper `aria-labels` on buttons (like the "X" close button) and ensures modals are announced correctly.
* **Focus Management:** Ensures that when a popup appears, the focus is "trapped" inside the popup so the user doesn't accidentally interact with the background page.

### **2. `auth` (Authentication Logic)**

Tests the core authentication flows from a functional perspective.

* **Login/Signup Success:** Verifies that valid credentials lead to a successful session.
* **Token Handling:** Checks if user data is correctly stored in the app's state after a successful response.
* **Logout:** Ensures the user session is cleared and the state returns to `null`.

### **3. `edge_cases` (Stress Testing)**

Handles the "what-ifs" and unusual user behaviors to prevent app crashes.

* **Rapid Clicks:** Ensures that double-clicking the "Submit" button doesn't trigger multiple server requests.
* **Network Failure:** Simulates a server timeout or a 500 error to ensure the `ErrorPopup` displays the correct "Connection Failed" message.
* **Long Inputs:** Tests how the UI handles extremely long usernames or emails.

### **4. `end_to_end` (User Journeys)**

Simulates a real human user interacting with the browser from start to finish.

* **The Full Cycle:** A user lands on the Home page, signs up, waits through the 10-second loading animation, sees the Success Popup, and is redirected to their profile.
* **Browser Interoperability:** Running these tests across different browsers (Chrome, Firefox, Safari) using Playwright.

### **5. `integration` (Component Communication)**

Tests how different parts of the app (Provider, Hooks, and UI) work together.

* **Provider to Popup:** Verifies that setting `isLoading` to `true` in the `AuthProvider` actually renders the `LoadingPopup` on the screen.
* **Timer Sync:** Ensures the `minWait` (10 seconds) logic correctly delays the closing of the loader even if the server responds early.

### **6. `logic` (Pure Calculations)**

Tests the "brain" of the app without needing a browser or UI.

* **Email Masking:** Verifies the `maskEmail` utility correctly turns `testuser@email.com` into `tes*****@e****.com`.
* **ID Formatting:** Ensures the random IDs generated by the server placeholders meet the expected string format (e.g., `USR-XXXX`).

### **7. `recovery` (Session Persistence)**

Ensures the app remains stable during interruptions.

* **Page Refresh:** Tests if a user remains logged in after hitting `F5` (checking `localStorage` re-hydration).
* **Interrupted Loading:** Checks what happens if the page is closed or refreshed while the 10-second loading animation is active.

### **8. `routing` (Protected Routes)**

Guards the security of your private pages.

* **Auth Guards:** Verifies that an unauthenticated user attempting to visit `/user-portal` is automatically redirected back to the Login page.
* **Redirect Logic:** Ensures the user is sent to the correct destination immediately after the Success Popup is dismissed.

### **9. `snapshot` (Visual Regression)**

Captures "photos" of the UI to detect unintended design changes.

* **Popup UI:** Compares the current look of the `SuccessPopup` and `ErrorPopup` against a "Gold Master" image.
* **Subtle Background:** Ensures the overlay opacity and blur effect remain consistent across different screen sizes.
